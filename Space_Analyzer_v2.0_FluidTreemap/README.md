# Space Analyzer 2.0 · 流体式磁盘空间分析器

基于上一版源码重构的跨平台磁盘空间分析器。Windows 桌面端使用 Electron / Node.js 本地扫描；Web 端使用浏览器文件夹授权 API。两端共享数据模型、筛选逻辑与 Fluid Treemap 绘制引擎。

## 2.0 主要变化

- Windows 扫描改为后台任务 + IPC 分批推送，不再等全部文件读完才一次性回传。
- 受控目录并发：同一批最多并行枚举 4 个目录，每个目录按 128 个条目分批处理；文件元数据采用批量并发 stat。
- 支持扫描暂停、继续、取消；显示已扫描文件数、文件夹数、累计文件逻辑大小、当前路径和错误数。
- 默认跳过符号链接、目录联接和特殊文件，避免循环遍历；无权限或临时失效目录会跳过并计入错误数。
- Fluid Treemap 使用递归 Power Diagram / 加权 Voronoi 分区，形状为不规则多边形并进行圆滑拐角处理；每级分区受父区域裁切。
- 文件夹和文件面积按逻辑大小分配；每层最多展示 18 个单元，剩余条目合并为“其他 N 项”，避免超大目录产生过多绘制负担。
- 单击选择、双击进入文件夹、滚轮或按钮调整嵌套深度、面包屑返回；名称与容量在足够大的区域中央显示。
- 修正 Electron 打包模式下仍然加载开发服务器的问题；Windows 包不再引用缺失的图标文件。

## 环境

- Node.js 20 或更新版本
- npm
- Windows 安装包建议在 Windows 环境构建；Web 版本可在任意支持 Node.js 的环境构建。

## Windows 开发运行

```bash
npm install
npm start
```

应用启动后点击“选择扫描位置”，选择整个卷（例如 `C:\`）或指定目录。扫描器只读取文件元数据，不会删除或更改文件。

## 构建 Web 版本

```bash
npm install
npm run build:web
```

Web 可以直接部署：将压缩包根目录的 `index.html` 与整个 `src/` 目录一起上传到静态网站根目录，无需安装 Node.js。也可以执行上述构建命令，再发布 `dist/`。优先使用最新版 Chrome / Edge 并通过 HTTPS 或 localhost 访问，以启用 `showDirectoryPicker()`；其他浏览器会回退到 `webkitdirectory` 文件选择。

## 构建 Windows 安装程序

```bash
npm install
npm run dist:win
```

安装包输出到 `release/`。Windows 安装包建议在 Windows 主机上构建并完成实际扫描测试。

## 自动化检查

```bash
npm test
```

布局测试会检查等面积、按权重分配和嵌套多边形覆盖；扫描测试会创建临时目录，验证 Electron 主进程的分批 IPC 输出、目录层级、文件数与容量统计。以上测试不需要真实磁盘或 Electron GUI。

## 当前统计口径与限制

1. 显示的是文件逻辑大小（File Size），不等同于 NTFS 实际分配簇大小。
2. 硬链接若通过多个路径被枚举，会按路径重复计入；当前版本尚未按文件 ID 去重。
3. 默认跳过符号链接、目录联接和其他特殊文件，以规避循环与越权路径。
4. 当前使用 Node.js `fs.opendir`、受控目录并发与分批 `stat`。这是通用文件系统扫描路径，不等于 NTFS USN Journal / MFT 原始索引级扫描；百万级目录仍需要在目标设备上做性能基准。
5. 扫描进度不显示虚构百分比，因为扫描前未知总项目数；显示已处理计数与当前路径。
6. Web 端只能访问用户主动授权的目录；浏览器不允许网页静默遍历整块硬盘。
7. 为限制绘制复杂度，每层显示容量最大的 17 项，其余聚合为“其他”；完整文件数据仍保留在文件列表与 CSV 导出中。
8. Power Diagram 的目标面积按文件大小近似拟合，布局会迭代平衡权重，不宣称每个像素面积绝对精确；零字节条目使用最小权重参与布局。
9. 当前版本只读，不包含删除、移动、清空回收站等危险操作。

## 项目结构

- `index.html`：桌面与网页共用入口
- `src/app.js`：扫描数据模型、Web 扫描适配、Fluid Treemap、筛选和导出
- `src/style.css`：莫兰迪暖灰界面与深色流体空间地图
- `desktop/main.cjs`：Electron 主进程和 Windows 扫描后台任务
- `desktop/preload.cjs`：受限 IPC 桥接
- `vite.config.js`：Web 构建配置

## 与 SpaceSniffer 的关系

参考 SpaceSniffer 的目录扫描、空间占用映射、层级导航等核心使用范式。用户提供的是编译后的 EXE，不含可直接编辑的原始项目源代码，因此本项目是独立重构，不修改原程序二进制，也不声称复用其内部算法。

## 性能说明与下一阶段

- Windows 扫描在主进程运行异步 I/O，目录枚举受控并发，文件 stat 分批并发执行，IPC 以 450 条记录为批次推送。
- 当前版本将扫描数据保存在渲染进程内存，以支持树层级、搜索、排行与 CSV；超大规模（数百万项目）场景仍建议下一阶段引入 SQLite/LevelDB 索引与虚拟滚动，并评估 NTFS USN Journal 加速。
- 本轮在通用 Node.js 文件系统环境验证了分批扫描数据完整性与空间分区几何覆盖；尚未在真实 Windows 多型号硬盘上完成速度基准，也未在本环境构建 Windows 安装程序。
